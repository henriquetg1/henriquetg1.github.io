    B — Build the model¶

    The architecture is the one specified: encoder \(784 \to 512 \to 256\), two heads \(256 \to d\) for \(\mu\) and \(\log\sigma^2\), and decoder \(d \to 256 \to 512 \to 784\) with a sigmoid output, using \(d = 16\). Three parts are hand-written in code/vae.py:

    • Reparameterization: \(z = \mu + \sigma \odot \epsilon\), with \(\epsilon \sim N(0, I)\) and \(\sigma = e^{\frac{1}{2}\log\sigma^2}\).
    • Reconstruction: F.binary_cross_entropy(x_hat, x, reduction="sum") divided by the batch size.
    • KL: the closed form \(\frac{1}{2}\sum_i(\mu_i^2 + \sigma_i^2 - 1 - \log\sigma_i^2)\), written out and divided by the batch size.
    The VAE, its loss and its training loop — code/vae.py 
    """A variational autoencoder for flattened MNIST, written by hand.

PyTorch provides the layers, autograd and Adam. The VAE-specific parts are all
here: the reparameterization, both terms of the loss, and sampling from the prior.
"""

import torch
import torch.nn.functional as F
from torch import nn

BATCH_SIZE = 128
LEARNING_RATE = 1e-3
EPOCHS = 20


class VAE(nn.Module):
    """Encoder 784 -> 512 -> 256, heads 256 -> d, decoder d -> 256 -> 512 -> 784."""

    def __init__(self, latent_dim):
        super().__init__()
        self.latent_dim = latent_dim
        self.encoder = nn.Sequential(
            nn.Linear(784, 512), nn.ReLU(),
            nn.Linear(512, 256), nn.ReLU(),
        )
        self.mu_head = nn.Linear(256, latent_dim)
        self.logvar_head = nn.Linear(256, latent_dim)
        self.decoder = nn.Sequential(
            nn.Linear(latent_dim, 256), nn.ReLU(),
            nn.Linear(256, 512), nn.ReLU(),
            nn.Linear(512, 784), nn.Sigmoid(),
        )

    def encode(self, x):
        hidden = self.encoder(x)
        return self.mu_head(hidden), self.logvar_head(hidden)

    def decode(self, z):
        return self.decoder(z)

    def reparameterize(self, mu, logvar):
        # z = mu + sigma * eps. The noise sits outside the path from mu and sigma,
        # so gradients can flow through both of them.
        sigma = torch.exp(0.5 * logvar)
        eps = torch.randn_like(sigma)
        return mu + sigma * eps

    def forward(self, x):
        mu, logvar = self.encode(x)
        z = self.reparameterize(mu, logvar)
        return self.decode(z), mu, logvar

    def sample(self, n):
        # z ~ N(0, I), the prior, pushed through the decoder
        z = torch.randn(n, self.latent_dim)
        return self.decode(z)


def loss_terms(x, x_hat, mu, logvar):
    """Return both loss terms in nats per image: summed over pixels, averaged over images."""
    batch_size = x.shape[0]
    reconstruction = F.binary_cross_entropy(x_hat, x, reduction="sum") / batch_size
    # Closed-form KL between N(mu, sigma^2) and N(0, I), summed over latent dimensions
    kl = 0.5 * torch.sum(mu**2 + logvar.exp() - 1 - logvar) / batch_size
    return reconstruction, kl


@torch.no_grad()
def evaluate(model, x):
    """Average both loss terms over a dataset, with z sampled as in training."""
    totals = torch.zeros(2)
    for batch in x.split(BATCH_SIZE):
        x_hat, mu, logvar = model(batch)
        reconstruction, kl = loss_terms(batch, x_hat, mu, logvar)
        totals += torch.stack((reconstruction, kl)) * batch.shape[0]
    return (totals / x.shape[0]).tolist()


def train(model, x_train, x_val, epochs=EPOCHS):
    """Train with Adam (beta = 1) and log both terms on train and validation each epoch."""
    optimizer = torch.optim.Adam(model.parameters(), lr=LEARNING_RATE)
    history = {"train_rec": [], "train_kl": [], "val_rec": [], "val_kl": []}

    for _ in range(epochs):
        model.train()
        totals = torch.zeros(2)
        for indices in torch.randperm(x_train.shape[0]).split(BATCH_SIZE):
            batch = x_train[indices]
            x_hat, mu, logvar = model(batch)
            reconstruction, kl = loss_terms(batch, x_hat, mu, logvar)
            loss = reconstruction + kl

            optimizer.zero_grad()
            loss.backward()
            optimizer.step()

            totals += torch.stack((reconstruction, kl)).detach() * batch.shape[0]

        # Training numbers are the running average over the epoch, as the statement asks
        train_rec, train_kl = (totals / x_train.shape[0]).tolist()
        model.eval()
        val_rec, val_kl = evaluate(model, x_val)

        history["train_rec"].append(train_rec)
        history["train_kl"].append(train_kl)
        history["val_rec"].append(val_rec)
        history["val_kl"].append(val_kl)

    return history

def load_data():
    """The statement's split, then all pixels as tensors so that an epoch takes seconds."""
    train_full = datasets.MNIST("data", train=True, download=True, transform=transforms.ToTensor())
    test = datasets.MNIST("data", train=False, download=True, transform=transforms.ToTensor())
    train_set, val_set = random_split(
        train_full, [50_000, 10_000], generator=torch.Generator().manual_seed(SEED)
    )

    # Same values as ToTensor: bytes divided by 255, flattened into 784-vectors
    pixels = train_full.data.float().flatten(1) / 255
    assert torch.equal(pixels[0], train_full[0][0].flatten())
    x_test = test.data.float().flatten(1) / 255
    return pixels[train_set.indices], pixels[val_set.indices], x_test, test.targets


def tile(images, rows, cols, size=28, gap=2):
    """Lay flattened images out on one canvas, with a faint line between the cells."""
    images = images.reshape(-1, size, size).detach().numpy()
    step = size + gap
    canvas = np.full((rows * step - gap, cols * step - gap), 0.12)
    for i, image in enumerate(images):
        row, col = divmod(i, cols)
        canvas[row * step : row * step + size, col * step : col * step + size] = image
    return canvas


def show_grid(images, rows, cols, title, xlabel, ylabel, name, xticks=(), yticks=(), scale=0.62):
    """Show a tile of images with a title, axis labels and optional tick labels."""
    fig, ax = plt.subplots(figsize=(cols * scale, rows * scale + 0.5))
    ax.imshow(tile(images, rows, cols), cmap="gray_r", vmin=0, vmax=1)
    centers = lambda n: [30 * i + 13.5 for i in range(n)]
    ax.set_xticks(centers(cols) if len(xticks) else [], xticks)
    ax.set_yticks(centers(rows) if len(yticks) else [], yticks)
    ax.set(title=title, xlabel=xlabel, ylabel=ylabel)
    ax.grid(False)
    for spine in ax.spines.values():
        spine.set_visible(False)
    fig.savefig(FIGURES / name)
    plt.close(fig)


def train_model(latent_dim, x_train, x_val):
    torch.manual_seed(SEED)  # before building each model, as the statement requires
    model = VAE(latent_dim)
    history = train(model, x_train, x_val)
    model.eval()
    return model, history


def plot_history(history):
    epochs = range(1, EPOCHS + 1)
    fig, axes = plt.subplots(1, 2, figsize=(9, 3.4))
    panels = (
        (axes[0], "rec", "Reconstruction (nats per image)", "Reconstruction term"),
        (axes[1], "kl", "KL (nats per image)", "KL term"),
    )
    for ax, key, ylabel, title in panels:
        ax.plot(epochs, history[f"train_{key}"], color=BLUE, label="Training")
        ax.plot(epochs, history[f"val_{key}"], color=ORANGE, label="Validation")
        ax.set(title=title, xlabel="Epoch", ylabel=ylabel)
        ax.set_xticks([1, 5, 10, 15, 20])
        ax.legend()
    fig.suptitle("Figure 1: both loss terms of the VAE with d = 16", color=INK)
    fig.tight_layout()
    fig.savefig(FIGURES / "fig1.png")
    plt.close(fig)

    )

    torch.manual_seed(0)
    show_grid(
        model.sample(64), 8, 8,
        "Figure 3: images decoded from $z \\sim N(0, I)$",
        "Sample column", "Sample row", "fig3.png", scale=0.8,
    )

    # Numbers for item E. Decoding mu against decoding a sampled z, on the whole test set:
    mu, logvar = model.encode(x_test)
    from_mu, _ = loss_terms(x_test, model.decode(mu), mu, logvar)
    print(f"Test reconstruction decoding mu: {from_mu:.2f} (decoding a sampled z: {test_rec:.2f})")

    # Do prior samples land where the encoded images are? Compare in the active dimensions
    # only: the decoder ignores the others, so noise there would inflate every distance.
    kl_per_dim = 0.5 * (mu**2 + logvar.exp() - 1 - logvar).mean(dim=0)
    active = kl_per_dim > 0.1
    print(f"KL per latent dimension: {kl_per_dim.numpy().round(2)}")
    print(f"Active dimensions (KL > 0.1): {int(active.sum())} of 16")
    tree = cKDTree(model.encode(x_train)[0][:, active].numpy())
    groups = (
        ("test mu", mu),
        ("z sampled from test posteriors", model.reparameterize(mu, logvar)),
        ("z sampled from the prior", torch.randn(10_000, 16)),
    )
    for name, points in groups:
        distance = tree.query(points[:, active].numpy(), workers=-1)[0]
        print(f"Distance to the nearest encoded training image, {name}: "
              f"median {np.median(distance):.2f}, 90th percentile {np.quantile(distance, 0.9):.2f}")
    return model, history, test_rec, test_kl

        torch.cat((pixel_row, latent_row)), 2, 10,
        f"Figure 6: from test image {a} to test image {b}",
        "$t$", "Interpolation space", "fig6.png",
        xticks=[f"{value:.2f}" for value in t.squeeze(1).tolist()],
        yticks=["Pixel", "Latent"], scale=0.85,
    )
    return test_rec, test_kl

    D — Reconstructions and samples¶

    Figure 2 uses the first test image of each digit, at test indices 3, 2, 1, 18, 4, 8, 11, 0, 61 and 7.

    E — Analysis¶

    Why would the optimizer pay more KL? Because the total is what it minimizes, and the trade is very favorable early on. A code that matches the prior says nothing about the image, so the decoder can only output something like an average digit. Moving each \(q(z \mid x)\) away from the prior costs KL but tells the decoder which image it is looking at. From epoch 1 to epoch 2 the training KL rose by 7.75 nats (6.85 to 14.60), while the reconstruction fell by 59.63 (175.88 to 116.25). The total still fell by 51.88. Part of that drop comes from the decoder simply getting better, but the direction of the trade is clear.

    Why does Figure 3 look worse than Figure 2?

    1. Where the samples land. Figure 2 decodes \(\mu\) from real images, a region the decoder was trained on. Prior samples can fall between the encoded clouds, where no training image lives. Eleven of the 16 dimensions are active (KL above 0.1), so distances are measured only in those. The median distance to the nearest encoded training image is 1.49 for prior samples, against 1.19 for \(z\) sampled from test posteriors, about 25% farther. At the 90th percentile it is 1.99 against 1.57. A code between clouds of different digits decodes to a hybrid, which is what the non-digits in Figure 3 look like.
    2. What the decoder outputs. For a given \(z\), the decoder returns one probability per pixel, and the loss-optimal value is the average of all images consistent with that code. Several sharp images average into a blurry one. The objective asks for this, so it is not a bug, and it happens even when \(z\) lands in a well-trained region.

    Why decode \(\mu\) in Figure 2? \(\mu\) is the center of \(q(z \mid x)\), the encoder's best single answer for that image. A sampled \(z\) adds noise \(\sigma\epsilon\), so the picture would change on every draw and would mix what the model retained with sampling noise. On the test set, decoding \(\mu\) costs 76.53 nats of reconstruction against 81.96 for a sampled \(z\). The reported 81.96 keeps the sample because that is the ELBO's term.

    E — Analysis¶

    Which digits overlap? Mainly 4 and 9, then 3 and 5. For 25.5% of the test points, the nearest neighbor in Figure 4 is a different digit. Counting those links per pair gives 574 for 4 and 9, and 423 for 3 and 5. The next pairs are 5 and 8 (229), 3 and 8 (194), and 7 and 9 (190). The medians of 4 and 9 are only 0.15 apart, at (0.32, 0.60) and (0.46, 0.55).

    Figure 5 shows the same transition. In the row \(z_2 = 0.70\), the images read as 4 up to \(z_1 = 0.16\) and as 9 from \(z_1 = 0.50\). Between them, at \(z_1 = 0.33\), the open top of the 4 is partly closed and smudged, an image that could be read as either digit. The bottom row shows the same for 3 and 5 around \(z_1 = 0.33\) to \(0.50\), where the top stroke changes shape. The in-between images are blurrier than those at the center of each digit's region.

    What do two numbers force the model to throw away? Style. The KL gives an upper bound on what the code carries per image: 6.69 nats at \(d = 2\). Naming a digit alone takes \(\ln 10 = 2.30\) nats, which leaves at most 4.39 nats for everything else, against 17.06 at \(d = 16\). Figure 5 is the evidence. A position in the plane decodes to exactly one image, and most of the plane goes to digit identity. What remains is mostly slant: the 1s in the right column lean more toward the bottom, and the 0s in the left column stand up. Stroke thickness, loop size and each writer's quirks have no axis of their own, so they get averaged away. That is where the extra 53.30 nats of reconstruction go.

    Which interpolation looks like digits? The latent row. The pixel row is a weighted overlay: at \(t = 0.44\) and \(0.56\) the ring of the 0 and the bar of the 1 appear together at partial intensity, which no digit looks like. A straight line between two images in pixel space leaves the set of digit images.

    The latent row always decodes a single shape: the ring narrows and collapses into the bar, reaching a clean 1 by \(t = 0.78\). The line between \(\mu_a\) and \(\mu_b\) stays in a space where the KL made the encoded clouds overlap, and the decoder learned to output digit-like images there. It is not perfect: at \(t = 0.44\) and \(0.56\) the images are blurry and look like a rough 8, because the path crosses the area between the two digits' regions.
